## Project documenting procedure
01. Prioritize the Purpose (WHY)
Explain **why the function exists in the project**.

02. Describe the Behavior (WHAT)
Explain **what the function does overall**, not every line.

03. Avoid Explaining Obvious Implementation (HOW)
04. Document Inputs and Outputs
05. Explain Complex Logic When Needed
If the function contains **tricky logic**, then explaining **how** can help.

## A Simple Rule
01. Why does this function exist?
02. What does it do?
03. What inputs and outputs does it have?
04. Only explain HOW if the logic is complex.
